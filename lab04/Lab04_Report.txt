1. The Deadlock (Phase 2):
Model A first acquired GPU 0 and then waited for GPU 1. At the same time, Model B acquired GPU 1 and waited for GPU 0. 
Model A could not continue because GPU 1 was held by Model B, while Model B could not continue because GPU 0 was held by Model A. 
Both models were waiting for each other, creating a Circular Wait and causing a deadlock.

2. The Solution (Phase 3):
Model B was changed to request GPU 0 first, just like Model A. This removed the Circular Wait condition because both models requested the resources in the same order. 
One model could acquire GPU 0 and continue, while the other had to wait without holding another resource.

3. Starvation vs Deadlock (Phase 4): The Starvation script eventually allows the processes to finish, although the Polite_Model may have to wait for a long time. 
In contrast, the Deadlock script causes the processes to wait forever and cannot finish without intervention.
A scheduler can use Aging by gradually increasing the priority of a process that has been waiting for a long time. 
This gives the Polite_Model a better chance to receive CPU time and prevents it from waiting forever.
